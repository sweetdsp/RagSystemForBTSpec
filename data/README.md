# Documents

| File | What it is |
|------|------------|
| `bluetooth_core_spec.pdf` | **Bluetooth Core Specification v5.4** (amended 2024-06-11), 3,141 pages, © Bluetooth SIG. The app's default document. |
| `sample_bluetooth_primer.pdf` | A ~6-page **self-written** educational primer (generated by `scripts/make_sample_pdf.py`), used automatically only when the spec above is absent. It is *not* the official specification. |

## How the app reads the spec

- **Section picker.** The PDF's bookmarks become the sidebar's *Jump to section* list (Vol → Part,
  e.g. *Vol 6: Low Energy Controller › Part A: Physical Layer Specification, pp. 2647–2664*). Picking
  one sets the page range; *Whole document* indexes all pages.
- **Citations.** Every chunk carries its Vol/Part breadcrumb, which is shown next to retrieved snippets
  and included in the prompt so the LLM can cite where an answer comes from.
- **Cleaning.** Running headers (*"Bluetooth SIG Proprietary"*, *"Version 5.4 | Vol 6, Part B page 2799"*,
  section titles) and glyph garbage from figures are removed before chunking.
- **Caching.** The first full parse takes about a minute (~20 ms/page). Page text and bookmarks are then
  cached in `.cache/` (git-ignored, ~1 MB), so later runs, even after a restart, start in seconds.
  Delete `.cache/` to force a re-parse.

Page numbers shown in the app are **PDF page numbers** (1-based), which are one higher than the page
numbers printed in the spec's headers (the cover is printed as "page 0").

To use a different version, replace the file (or upload one in the sidebar). The cache is keyed by the
file's hash, so a new file is parsed fresh.
